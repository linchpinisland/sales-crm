# 싼 모델이 첫 시도에 통과한 지시문, 해부해보면 5칸이다

2026-09-17 실측: 원본 `src/Rules.gs`(304줄)를 지우고 **Sonnet**에게 아래 지시문 하나를 줬더니 13개 테스트를 **첫 시도에** 통과했습니다. 비결은 모델이 아니라 지시문의 구조였습니다. 그 구조는 새로 만든 게 아니고, 전자책 「클로드 코드 업무 자동화」 1장의 **5요소 워크시트**(입력·규칙·작업·출력·검증)와 4장의 **계획 먼저 받기**(읽을 파일·만들 파일·수정할 파일·위험 작업·검증·승인)를 그대로 채운 것입니다.

## 1. 실제로 준 지시문 (원문)

```
작업 폴더: (이 리포 사본)

이 폴더는 Google Apps Script 기반 "영업사원 1인용 고객관리 도구"입니다.
src/Rules.gs(알림 규칙 엔진, 순수 함수)가 삭제된 상태입니다.
당신의 과제는 설계서와 테스트만 보고 src/Rules.gs를 처음부터 다시 구현해
node dev/run-tests.js의 13개 테스트를 전부 통과시키는 것입니다.

규칙:
- 절대 금지: 원본 Rules.gs를 찾거나 git 이력, 다른 폴더를 뒤지지 마세요. 이 폴더 안의 파일만 읽습니다.
- 읽어야 할 것: docs/spec.md(3장 스키마, 4장 알림 규칙, 5장 발송), src/Config.gs(상수·헤더·기본 규칙),
  src/Test.gs(테스트가 호출하는 함수 이름·인자·기대값), dev/run-tests.js(로드 방식),
  그리고 DemoData.gs·Dashboard.gs·Triggers.gs·Code.gs·SheetRepo.gs에서 Rules 함수를 어떻게 호출하는지.
- Rules.gs는 SpreadsheetApp 등 Apps Script 서비스를 쓰면 안 됩니다(Node vm에서 그대로 실행됨).
  함수 선언은 function name(...) 형태의 전역 함수로.
- 다른 파일은 수정하지 마세요. 오직 src/Rules.gs만 새로 씁니다.
- 구현 후 node dev/run-tests.js를 실행해 결과를 확인하고, 실패하면 고칩니다. 최대 8회 반복.

마지막 보고에 반드시 포함:
(1) 최종 테스트 결과 원문(마지막 15줄) (2) 시도 횟수
(3) 어디서 막혔고 무엇을 보고 풀었는지 3줄 (4) 구현한 함수 목록.
```

## 2. 해부 — 지시문의 각 줄이 책의 어느 칸인가

| 지시문의 줄 | 책의 칸 | 왜 필요한가 (빠지면 생기는 일) |
|---|---|---|
| "이 폴더는 ○○ 도구입니다. Rules.gs가 삭제된 상태입니다." | **1장 · 상황 한 줄** (신입사원 비유: 무슨 회사, 무슨 일) | 없으면 모델이 코드베이스 전체를 훑느라 사용량을 태우고 엉뚱한 파일을 고침 |
| "설계서와 테스트만 보고 … 13개 테스트를 전부 통과" | **출력** (무엇을 만들어야 끝인가) | 끝 조건이 없으면 "대충 비슷한 것"에서 멈춤 |
| "읽어야 할 것: spec.md 3·4·5장, Config.gs, Test.gs, 호출부" | **입력** + 4장 "읽을 파일" | 싼 모델 실패의 1순위 원인. 읽을 곳을 지목하면 지어내는 게 줄어듦 |
| "절대 금지: 원본·git·다른 폴더 뒤지지 말 것" | **규칙** + 2장 CLAUDE.md "파일 보호" | 실험의 정직성. 실무에선 "지난달 파일 건드리지 마" |
| "SpreadsheetApp 금지, 전역 function 형태" | **규칙** (회사 기준·양식) | 회사 양식·문체·금지사항 자리. 책의 "규칙 칸을 못 채우면 암묵지"가 이것 |
| "다른 파일은 수정하지 마세요. Rules.gs만" | 4장 "만들 파일 / 수정할 파일" | 범위를 안 정하면 맞던 부분까지 바꿔 돌아옴(4장 "다시 해줘의 함정") |
| "테스트 돌려서 실패하면 고칩니다. 최대 8회" | **검증** + 4장 오류 처리 5단계 + 반복 상한 | 검증 없이는 "그럴듯한 오답"이 통과. 상한 없이는 무한 루프로 사용량 소진 |
| "마지막 보고: 결과 원문·시도 횟수·막힌 곳·함수 목록" | 2장 CLAUDE.md "보고 방식" + 4장 승인 | 사람이 마지막에 확인할 재료. 이게 있어야 승인 판단이 30초 |
| (모델 = Sonnet) | **3장 모델 선택**: 설계는 추론형, 구현은 균형형 | 설계서가 이미 있으니 구현은 균형형으로 충분 |

**결론**: 지시문 9줄 중 7줄이 책의 5칸이고, 나머지 2줄은 4장의 계획·보고 형식입니다. 새로 배울 게 아니라 **워크시트를 채운 것**입니다.

## 3. 그대로 복사해 쓰는 뼈대 (낮은 모델용)

```
[상황] 이 폴더는 ○○입니다. 지금 ○○가 없는/틀린 상태입니다.
[출력] 끝 조건: ○○가 만들어지고 ○○로 확인되면 끝.
[입력] 읽어야 할 것: ○○, ○○ (그 외는 읽지 말 것)
[규칙] 지켜야 할 것: ○○ 형식 / ○○ 금지 / 회사 기준 ○○
[범위] 수정 가능: ○○만. 나머지 파일은 손대지 말 것.
[검증] 끝나면 ○○로 확인. 실패하면 원인 한 줄 → 수정 → 재확인. 최대 N회.
[보고] 마지막에 (1) 확인 결과 원문 (2) 시도 횟수 (3) 막힌 곳과 푼 방법 (4) 바꾼 파일 목록.
```

빈칸이 안 채워지는 줄이 있으면 그게 "자동화 전에 사람이 먼저 정리해야 하는 영역"입니다(책 1장). 특히 **[검증]이 비면 싼 모델을 쓰면 안 됩니다.** 검증 수단(테스트·대조표·샘플 정답)이 있을 때만 균형형 모델로 내려갑니다.

## 5. 한 줄 지시로도 되나 — 실측 (2026-09-17, 같은 날 2차)

같은 조건(원본 삭제, Sonnet)에서 **한 줄**만 줬습니다: *"spec.md 4장 알림 규칙을 순수 함수로 다시 구현해줘. 기존 src/Rules.gs는 보지 말고. 끝나면 node dev/run-tests.js로 확인해."*

| | 9줄 지시문(§1) | 한 줄 지시 |
|---|---|---|
| 결과 | 13/13 통과 | 13/13 통과 |
| 시도 | **1회** | **2회** (1차 12/13 — 상담·구매 행에 고객명이 없을 때 `{고객명}` 치환 실패 → 고객 정보 병합 추가) |
| 도구 호출 | 8회 | 17회 |
| 모델이 스스로 한 일 | 지목한 파일만 읽음 | 읽을 파일을 **스스로 탐색**(spec·run-tests·Test·Config·DemoData·Dashboard·preview) |
| 산출물 | [`Rules.sonnet-reimpl.gs.txt`](Rules.sonnet-reimpl.gs.txt) | [`Rules.sonnet-oneline.gs.txt`](Rules.sonnet-oneline.gs.txt) |

**읽는 법.** 한 줄로도 됐습니다. 그러면 5칸이 필요 없느냐 — 아닙니다. 한 줄 지시가 통과한 이유는 그 한 줄 안에 이미 **입력(spec.md 4장)·규칙(순수 함수, 원본 금지)·검증(run-tests)** 세 칸이 들어 있었기 때문입니다. 책 1장이 "처음엔 입력·작업·출력 3칸만"이라고 하는 것과 같은 얘기입니다. 그리고 빠진 두 칸(범위·보고)의 값은 **탐색 2배(도구 호출 8→17)와 재시도 1회**로 지불했습니다. 이 도구는 작아서 그 비용이 몇 분이지만, 파일이 수십 개인 회사 폴더에서는 그게 사용량 한도와 엉뚱한 파일 수정으로 돌아옵니다.

정리: **싼 모델을 쓰는 조건은 "검증 수단이 지시문에 들어 있는가"**이고, 나머지 칸은 탐색 비용과 사고 위험을 줄이는 칸입니다.

## 6. 그래서 비개발자는 어떻게 — 5칸을 AI가 채우게 한다 (실측 3차, 2026-09-17)

§1의 9줄은 개발자가 쓰는 지시문이고, 일반 직장인에게 "이렇게 쓰세요"는 허들입니다. 그래서 세 번째로 **쉬운 한국말 한 줄 + "계획 먼저"**만 줬습니다.

```
src/Rules.gs 파일이 없어졌어. docs/spec.md 보고 다시 만들어줘.
근데 바로 만들지 말고, 먼저 계획을 다섯 줄로 보여줘.
뭘 읽을지, 뭘 지킬지, 뭘 만들지, 뭐가 되면 끝인지, 뭘로 확인할지.
내가 "응" 하면 그때 진행해.
```

Sonnet이 낸 계획(요지): ① 읽기 — spec §3~5 + Triggers/Dashboard/Test/Code에서 호출부 역산 ② 지킬 것 — 순수 함수, SpreadsheetApp 미사용, 기존 스타일 ③ 만들 것 — 조건 4종 평가·전체 평가·템플릿 치환 ④ 끝 기준 — 호출부가 기대하는 함수가 다 있고 테스트가 로드됨 ⑤ 확인 — `node dev/run-tests.js`.
**§1의 9줄과 사실상 같은 내용을 AI가 스스로 썼습니다.** 사람은 "응" 한 글자.

| | 9줄 지시문 | 한 줄 지시 | 한 줄 + 계획 먼저 |
|---|---|---|---|
| 사람이 쓴 것 | 9줄 | 1줄 | 1줄 + "응" |
| 결과 | 13/13 | 13/13 | 13/13 |
| 시도 | 1회 | 2회 | 2회(12/13 → 13/13, 독립 재실행으로 확인) |
| 5칸을 쓴 주체 | 사람 | 없음(3칸만 한 줄에 내포) | **AI** — 사람은 읽고 승인 |
| 산출물 | Rules.sonnet-reimpl | Rules.sonnet-oneline | [`Rules.sonnet-plan.gs.txt`](Rules.sonnet-plan.gs.txt) |

**결론 — 비개발자용 지시문은 이 한 줄이면 됩니다.**

> "○○ 해줘. 근데 바로 하지 말고 먼저 계획을 다섯 줄로 보여줘. 뭘 읽을지, 뭘 지킬지, 뭘 만들지, 뭐가 되면 끝인지, 뭘로 확인할지. 내가 응 하면 진행해."

5칸은 사람이 채우는 표가 아니라 **AI에게 시키는 질문 다섯 개**입니다. 계획을 읽고 이상한 칸(특히 "뭘로 확인할지"가 비었으면)만 고치라고 하면 됩니다. 클로드 코드 앱의 계획 모드가 이 동작을 버튼으로 제공하고, 책 4장 「실행 전 계획」이 같은 내용입니다. 한 번 승인한 계획은 저장해 두면(11장 스킬) 다음부터는 한 줄도 안 씁니다.

## 7. 시청자 업무로 다시 (실측 4차, 2026-09-17) — 영상에 쓰는 실험은 이것

§1~§6은 "Rules.gs를 다시 만든다"는 개발자 실험이라 비개발자에겐 소재 자체가 허들입니다. 그래서 영상 본편 업무 그대로, **데모 CSV 3개로 "이번 주 챙길 5곳"**을 Sonnet에게 쉬운 한 줄 + "계획 먼저"로 시켰습니다.

지시문(전문): *"이 폴더에 고객.csv, 상담기록.csv, 구매기록.csv 있어. 오늘은 2026-09-16이야. 이번 주에 내가 꼭 연락해야 할 고객 5곳을 뽑아줘. 왜 지금인지랑, 전화하면 첫 마디를 뭐라고 할지도 같이. 근데 바로 하지 말고, 먼저 계획을 다섯 줄로 보여줘. 뭘 읽을지, 뭘 지킬지, 뭘 만들지, 뭐가 되면 끝인지, 뭘로 확인할지. 내가 "응" 하면 그때 진행해."*

Sonnet의 계획(요지): 세 파일만 읽음 / 없는 정보는 추측 안 함, 외부로 안 보냄 / 5곳마다 근거+첫 마디 / 근거가 원본 행에 있으면 끝 / 원본 행과 대조해 확인. → "응".

| 확인 항목 | 정답(코드 계산) | Sonnet 1차 | 판정 |
|---|---|---|---|
| 미수금 합계 | 27,500,000 | 27,500,000 | ✅ 대시보드와 일치 |
| 세광기계 미수 | 8,900,000 / 18일 경과 | 8,900,000 / **19일** | ❌ 하루 오차 (오늘을 9/17로 잡고 암산) |
| 오름테크 미수 | 2,700,000 / 5일 경과 | 2,700,000 / **6일** | ❌ 같은 원인 |
| 파일 저장 | 작업 폴더에 `이번주_챙길고객.md` | "저장 완료" 보고 — **실제로는 다른 폴더에 씀** | ❌ 지시 위반("이 폴더 밖은 보지 마") |
| 5곳 선정 | (판단 영역) | 미래에듀·세광기계·푸른바이오·오름테크·라온교육 | 스킬 예시와 3/5 일치, 나머지는 "다음 액션일 임박" 기준 — 타당 |

후속 한 줄 *"오늘은 2026-09-16이야, 경과일 다시 계산해. 파일이 이 폴더에 있는지 ls로 확인해서 알려줘"* → 18일·5일로 수정, 파일 생성 확인. 산출물: [`이번주_챙길고객_sonnet_계획먼저.md`](이번주_챙길고객_sonnet_계획먼저.md).

**영상 메시지(최종)**: 싼 모델로 결과는 나온다. 대신 그럴듯하게 틀린다(하루 오차·가짜 저장). **확인할 숫자 하나(대시보드 미수금 합계)만 정해두면 걸리고, 한 줄이면 고쳐진다.** 그래서 다섯 칸 중 "뭘로 확인할 거야"가 핵심이고, 그 칸은 시청자가 쓰는 게 아니라 AI에게 묻는 질문이다. 스킬 `sales-weekly-picks`는 "계산은 코드로"가 들어 있어 이 오차가 애초에 안 난다.
