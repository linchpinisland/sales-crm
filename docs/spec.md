# 설계 스펙 — 영업사원 1인용 고객관리 도구 (Sales CRM)

작성 2026-09-16. 유튜브 영상 「영업팀 클로드 코드 자동화 3가지」 시연 도구이자 책 자료팩 배포용 템플릿.

## 1. 목표와 제약

- 비개발자 영업사원이 **구글 시트 사본 만들기 → 메뉴에서 초기 설정 → 웹앱 배포** 3단계로 쓸 수 있어야 한다.
- 서버 비용 0. 개인 구글 계정 + 개인 카카오 계정만으로 동작.
- 사용자 1인. 로그인·권한 없음(웹앱은 "나만 접근").
- 인사이트 도출은 앱 안 LLM 호출이 아니라 **CSV 내보내기 → Claude Code 스킬**로(영상 메시지 "폴더 하나 + 스킬").

## 2. 아키텍처

```
구글 시트 (유일한 DB)
 └─ 컨테이너 바인드 Apps Script
     ├─ 커스텀 메뉴 [고객관리]   초기 설정 / 미리보기 / 발송 / 데모 / CSV
     ├─ HtmlService 웹앱        대시보드 · 고객 · 기록 입력 · 설정 (모바일 대응)
     ├─ 시간 트리거             매일 08시 요약, 주 1회 토큰 갱신
     ├─ 설치형 onEdit 트리거    편집 행에 대해 즉시발송 규칙 평가
     └─ doGet 콜백              카카오 OAuth (/exec?code=…)
카카오 "나에게 보내기" API ← ScriptProperties 토큰
이메일 폴백 (MailApp) ← 카카오 미연결/실패 시
```

순수 함수 계층(`Rules.gs` `DemoData.gs` `Dashboard.gs` `Config.gs`)은 SpreadsheetApp 을 쓰지 않아 Node 에서 그대로 테스트·미리보기한다(`dev/`).

## 3. 시트 스키마

| 탭 | 컬럼 |
|---|---|
| 고객 | 고객ID(C001) · 고객명 · 담당자 · 연락처 · 업종 · 단계(잠재/견적발송/협상/거래중/휴면/이탈) · 단계변경일 · 구매의향(상/중/하) · 마지막연락일(캐시) · 생일 · 기념일 · 고민포인트 · 취향/선호 · 다음제안아이디어 · 메모 · 등록일 |
| 상담기록 | 기록ID(L0001) · 상담일 · 고객ID · 고객명 · 유형(방문/전화/카톡/이메일/견적발송/기타) · 내용 · 결과(대기/진행/성사/보류/실패) · 다음액션 · 다음액션일 · 등록일시 |
| 구매기록 | 구매ID(P0001) · 구매일 · 고객ID · 고객명 · 제품/서비스 · 특징/사양 · 금액 · 재구매주기(일) · 다음구매예정일 · 계약만료일/납기일 · 수금예정일 · 수금상태(미수/완료/부분) · 구매당시의향 · 고민포인트 · 다음제안 · 메모 |
| 알림규칙 | 규칙ID · 규칙명 · 사용 · 대상시트 · 기준필드 · 조건유형 · 일수 · 필터 · 메시지템플릿 · 즉시발송 · 정렬순서 |
| 알림로그 | 발송일시 · 규칙ID · 고객ID · 고객명 · 메시지 · 채널 · 상태 · 오류 · 중복키(`YYYY-MM-DD|규칙ID|고객ID`) |

**마지막연락일**은 상담일·구매일의 최대값을 캐시로 써 둔다(직접 입력도 허용, 갱신은 `max(현재값, 기록)`). 헤더 이름 기반으로 읽어 컬럼 순서를 바꿔도 된다.

## 4. 알림 규칙

조건유형 4가지: `경과일이상`(기준일→오늘 ≥ N) · `D일이내`(오늘→기준일 0~N) · `연간반복D일이내`(생일처럼 매년, 2/29는 평년 2/28) · `필드값일치`(필터만). 필터는 `필드=값;필드!=값`. 템플릿 플레이스홀더 `{고객명} {일수} {D-표기} {기준일}` + 임의 컬럼명.

기본 규칙 R01~R07(ON): 장기 미접촉 21일 / 견적 후 무응답 7일 / 재구매 주기 도래 D-7 / 계약·납기 만료 D-7 / 미수금 기일 경과 / 담당자 생일 D-3 / 거래처 기념일 D-3. 예시 R08(다음 액션 도래)·R09(구매의향 상 전환, 즉시발송)는 OFF로 선탑재.

같은 규칙·같은 고객은 가장 급한 1건만. 정렬은 규칙 정렬순서 → 급한 순.

## 5. 발송

- `dailyDigest`: 마지막연락일 갱신 → 전체 평가 → 알림로그 중복키 제외 → 요약 청크(카카오 텍스트 200자) 발송 → 로그.
- 즉시발송: onEdit(편집 행 1개) 또는 웹앱 저장 직후 `evaluateImmediateForRow` → 건별 발송, 같은 날 같은 고객·규칙 1회.
- 채널: 카카오 → 실패/미연결 시 이메일 폴백(설정 Y).

## 6. 카카오 "나에게 보내기"

REST API 키·웹앱 URL은 설정 탭, 토큰은 ScriptProperties. 인가 → `/exec?code=` 콜백 → 토큰 교환 → 완료 페이지 + 테스트 발송. 액세스 토큰은 발송 직전 만료 5분 전이면 갱신, 리프레시 토큰은 응답에 새 값이 오면 교체. 갱신 실패 시 DISCONNECTED + 이메일 안내 + 대시보드 배너.

구현 시 실측 항목: (a) 카카오 콘솔의 `script.google.com` Redirect URI 허용 여부 (b) 링크 버튼 도메인 등록 필요 여부(실패 시 텍스트만 재시도 구현됨) (c) 비즈앱 전환 없이 가능한지.

## 7. 웹앱

단일 페이지 해시 라우팅(`#dash #customers #customer/ID #forms/{customer|contact|purchase} #settings`). 데스크톱 상단 네비 + 모바일 하단 탭바. 서버 응답의 Date 는 `YYYY-MM-DD` 문자열로 직렬화. 차트는 라이브러리 없는 SVG(6개월 매출 막대, 단계별 도넛). Open Props 토큰을 `:root` 시맨틱 변수로 재매핑(진단기와 동일).

## 8. 데모 데이터

거래처 25곳·상담 40건·구매 35건. 날짜는 실행일 기준 오프셋이라 언제 넣어도 R01~R07이 각각 1건 이상 걸리고 경계 케이스(20일, D-8, 수금완료, 이탈)는 안 걸린다. `resetForDemo` 로 촬영 리허설.

## 9. Claude Code 스킬

`skills/sales-weekly-picks` — CSV 3개(또는 xlsx) → 이번 주 챙길 5곳과 이유·첫 마디, 고객별 다음 제안, 데이터 품질 메모. 우선순위: 미수금 > 견적 대기 > 재구매/만료 > 의향 상 미접촉 > 장기 미접촉 > 기념일. 보조 `scripts/summarize.py`(표준 라이브러리만).

## 10. 범위 밖

다중 사용자·권한, 알림톡(비즈메시지), 앱 안 LLM 호출, 1만 행 이상 데이터, 자동 백업.
