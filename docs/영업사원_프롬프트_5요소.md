# 영업사원이 그대로 붙여넣는 프롬프트 — 전자책 1장 5요소 워크시트 버전

실측 2026-09-17. 모델 Sonnet(Claude Code 서브에이전트). 빈 폴더 `~/Desktop/sales-crm-sonnet-5요소`에서 시작.
이 문서의 목적은 하나다. **Fable로 만든 이 도구를, 코딩 모르는 영업사원이 Sonnet으로도 만들 수 있는 프롬프트를 확정**하는 것.

| 이전 시도 | 문제 |

## 2. 확정 프롬프트 (전자책 1장 워크시트를 말로 채운 것)

책 1장 「내 업무에 적용하기 — 5요소 워크시트」의 다섯 칸(입력·규칙·작업·출력·검증)을 영업사원 말로 채우고,
책 4장 「실행 전 계획」의 한 문단을 끝에 붙인다. 파일 이름·함수 이름·기술 용어 0개.

```text
나는 자동차 영업사원이야. 코딩은 전혀 몰라. 내 고객 챙기는 걸 도와주는 도구를 만들고 싶어.

입력: 내 고객 명단이랑 상담 기록, 구매 기록. 지금은 엑셀 여기저기 흩어져 있어. 구글 시트 하나에 정리해서 쓰고 싶어.
규칙: 21일 넘게 연락 안 한 고객, 견적 보내고 일주일 넘게 답 없는 고객, 재구매 시기 일주일 전인 고객, 미수금 기일 지난 고객, 생일이나 기념일 3일 전인 고객은 꼭 챙겨야 해. 회사 실제 고객 파일은 넣지 말고 가짜 데이터로 시작해.
작업: 매일 아침 8시에 오늘 챙길 고객 목록을 카톡으로 나한테 보내줘. 카톡이 안 되면 이메일로 보내줘.
출력: 구글 시트 하나. 시트 메뉴에 초기 설정, 미리보기, 지금 보내기 버튼. 폰에서 보는 대시보드 페이지도 하나.
검증: 가짜 데이터로 돌렸을 때 규칙마다 최소 1명은 걸리는지, 같은 고객이 같은 날 두 번 안 오는지 표로 보여줘.

바로 만들지 말고 먼저 계획을 보여줘. 읽을 파일, 만들 파일, 위험한 작업, 검증 방법, 내가 승인해야 하는 단계. 내가 응 하면 진행해.
```

책과의 대응: 입력·규칙·작업·출력·검증 = 1장 5요소. "회사 실제 파일은 넣지 말고 가짜 데이터로" = 6단 절차 ①입력 분리. 마지막 문단 = 4장 실행 전 5점검. "내가 응 하면" = 6단 ⑤사람 승인.

## 3. 실측 — 1턴(계획)과 2턴(제작)

**1턴.** 파일을 하나도 만들지 않고 계획만 냈다. 만들 것·읽을 파일(없음)·만들 파일·위험 작업 4개·검증표 2개·승인 필요 단계 5개. 책 4장 형식 그대로.
단, Sonnet이 **"카카오 개인 발송 API는 사실상 없다"며 이메일 우선을 제안**했다. 이건 틀린 정보다(카카오 "나에게 보내기"는 개인 계정으로 된다). 사람 승인 단계가 있었기에 여기서 잡혔다.

**2턴 입력(영업사원 정정 한 문장).**
```text
응. 근데 카톡은 "카카오 나에게 보내기"라는 기능이 있대. 내 카카오 계정으로 나한테만 보내는 거. 그걸로 해줘. 안 되면 이메일로.
구글 계정 로그인이랑 배포 버튼은 내가 누를게. 그것만 빼고 파일은 다 만들어줘. 검증표도 지금 만들어서 보여줘.
```

**2턴 결과.** 파일 5개: `Code.gs`(276줄) · `대시보드.html` · `data/fake_customers.json`(10명) · `verify.js` · `README.md`. 검증표 2개를 `node verify.js`로 실제 실행해 붙임(규칙 5개 모두 ≥1명, 5개 규칙 전부 걸린 고객도 발송 1회).

| 항목 | Fable 원본 | Sonnet 2턴 |
|---|---|---|
| 시트 탭 | 7 (알림규칙·알림로그·_메타 포함) | 5 (규칙은 코드 고정, 로그 없음) |
| 메뉴 | 초기 설정/미리보기/발송/데모/CSV | 초기 설정/미리보기/지금 보내기 |
| 매일 8시 트리거 | ○ | ○ (재설치 시 기존 트리거 제거까지) |
| 카카오 나에게 보내기 | OAuth 콜백 + 토큰 자동 갱신 | 액세스 토큰 수동 입력 (수 시간 뒤 만료) |
| 이메일 폴백 | ○ | ○ |
| 대시보드 웹앱 | 4탭 | 1페이지 카드 목록 |
| 가짜 데이터 | 메뉴 버튼으로 시트에 주입 | JSON 파일만 (사람이 붙여넣어야) |
| 같은 날 중복 발송 방지 | 알림로그 중복키 | 없음 |

## 4. 3턴 — 빠진 셋을 사람 말로 고치기

(실측 결과 아래에 기입)

**3턴 입력(기술 용어 없음).**
```text
고마워. 세 개만 고쳐줘.
1. 가짜 데이터를 내가 손으로 붙여넣기 싫어. 메뉴에 "가짜 데이터 넣기" 버튼 추가해줘.
2. 카카오 토큰을 내가 복사해서 넣으면 몇 시간 뒤에 끊긴다며. 처음에 한 번만 로그인하면 알아서 계속되게 해줘.
3. "지금 보내기"를 하루에 두 번 누르면 같은 고객이 두 번 오지 않게 해줘.
고치기 전에 뭘 바꿀지 세 줄로 먼저 말해주고, 바로 진행해. 끝나면 검증표 다시 보여줘.
```

**3턴 결과.** `Code.gs` 276→511줄. 메뉴 `가짜 데이터 넣기`(`seedFakeData`), 메뉴 `카카오 연결하기` + 웹앱 `doGet` 콜백 + 리프레시 토큰 자동 갱신(`ensureFreshKakaoToken_`), `발송로그` 탭으로 같은 날 중복 제외. 검증표 3(같은 날 두 번 클릭: 2번째 신규 발송 0명) 추가. `node verify.js` 3표 모두 PASS.
Sonnet이 스스로 잡은 순서 제약: 카카오 리다이렉트 주소가 웹앱 URL이라 **배포를 카카오 연결보다 먼저** 해야 함 → README 순서 수정. (Fable 원본 `docs/카카오연동.md`와 같은 결론.)

3턴 후 Fable 원본과 남은 차이: 알림규칙 탭(규칙을 시트에서 편집) · 즉시발송 onEdit · 대시보드 4탭 · CSV 내보내기. 모두 "규칙을 시트에서 바꾸고 싶어" 같은 한 문장으로 추가 가능한 것들이지 허들이 아님. 영상에서는 여기서 멈춘다.

## 5. 결론 — 영상용 한 줄

- **허들을 없앤 건 프롬프트 길이가 아니라 워크시트 형식이다.** 9줄 개발자 지시문과 이 프롬프트는 길이가 비슷하다. 차이는 다섯 칸의 이름(입력·규칙·작업·출력·검증)이 책 1장에 있고, 칸마다 "내 업무 말"로 채우면 된다는 것.
- **Sonnet으로 3턴 = 계획 1턴 + 제작 1턴 + 사람 말 수정 1턴.** 총 토큰 약 27만(서브에이전트 실측 63k+87k+116k).
- **사람 승인이 잡은 것 1건:** "카카오 개인 발송 API 없다"는 Sonnet의 오답. 영업사원이 기능 이름 하나("카카오 나에게 보내기")만 알면 정정된다. 영상에서 이 단어를 알려주는 게 CTA 앞 가치.
- 6단 절차 대응: ①입력 분리(가짜 데이터) ②회사 규칙(규칙 칸 5개) ③초안(2턴) ④검증표(verify.js 3표) ⑤사람 승인(1턴 계획·카카오 정정) ⑥기록·갱신(발송로그 탭, 3턴).
